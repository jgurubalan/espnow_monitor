## 3. ACK Packet Format

20 bytes | Planned protocol

| Byte Positions | Field           | Value / Description                          |
| -------------- | --------------- | -------------------------------------------- |
| 0–3            | Signature       | `24JD`                                       |
| 4              | Version         | `0x01`                                       |
| 5              | ACK Type        | `0x06`                                       |
| 6–7            | Original Length | Original message length, little-endian       |
| 8–11           | CRC32           | Checksum of original message                 |
| 12–19          | Timestamp       | UTC Unix time in milliseconds, little-endian |

ACK signature in hexadecimal:

```
32 34 4A 44
```

Complete ACK header:

```
32 34 4A 44 01 06
```

- `32 34 4A 44` = `24JD`
- `01` = Protocol version 1
- `06` = ACK message type
- Timestamp is generated by the gateway when creating the ACK.
- IST is calculated from UTC by adding 5 hours and 30 minutes.

## Important Technical Notes

1. The gateway dashboard is accessed using its IP address. ESP-NOW communication uses MAC addresses.
2. Gateway and station firmware must use the same ACK signature, version, packet length and field layout.
3. ESP-NOW send success confirms link-layer transmission status, not application-level ACK validation.
4. ACK packets are not themselves acknowledged.
5. The 20-byte ACK format above is the planned format and must be implemented consistently in both gateway and receiving station firmware.
